# API coverage

Last audited (UTC): 2026-06-29

This file tracks the official Wix API-reference boundary for this tool. The current ledger has zero real callable `not-yet-implemented` rows: callable families are implemented with explicit named commands, and non-command surfaces are accounted as gated, callback-only, developer-preview, deprecated, docs-only, site-defined, or disabled.

## Coverage status model

- `implemented`: explicit named CLI command exists and is covered in this tool
- `gated`: official family exists, but Wix docs put real access behind a contract, selected beta, app install, or permission gate
- `callback-only`: official family is event-, webhook-, or service-plugin-driven instead of a normal CLI call
- `developer-preview`: official family or method is marked Developer Preview in Wix docs
- `docs-only`: official docs describe documentation, skills, SDK/client setup, or AI-tool instructions rather than a callable Wix API surface
- `site-defined`: official surface invokes customer-defined site code through a generic function name, so exposing it would be a forbidden call-anything bridge
- `disabled`: official family is documented but should not be exposed because Wix has discontinued the product or removed the backing data surface
- `not-yet-implemented`: official callable family exists, but this tool has not shipped named commands for it yet

Hard boundary rules:

- no generic REST request bridge
- no generic GraphQL bridge
- no generic jobs-runner bridge
- shipped coverage only counts when there is an explicit named command
