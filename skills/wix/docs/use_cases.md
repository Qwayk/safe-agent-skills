# Use cases

If your Wix account has grown across sites, apps, stores, bookings, members, campaigns, and CMS data, start by asking for a clear read of what is connected before you approve any change.

## Good first asks

- “Check this Wix setup and tell me which auth path works, which site or account it can see, and what is safe to review first.”
- “List the connected domains, DNS records, published site URLs, and app installation state so I know what is tied to this account.”
- “Show me the Wix Stores products, inventory items, catalog version, categories, and coupons that need review before a sale.”
- “Check appointment, class event, or multi-service booking availability, extended bookings counts, service setup, service options and variants, staff members, non-staff resources, resource types, Bookings-visible calendar schedules, and external calendar connections for this filter, then explain whether the site looks ready for scheduling work.”
- “Review email sender setup, sending domains, marketing consent, and draft campaign status before I approve any send.”
- “Prepare a careful plan to update CMS fields, data permissions, coupons, pricing plans, or products, but stop before live changes.”

## Common jobs this skill should help with

- Understand which Wix account, site, app instance, and permission scopes the agent is actually using.
- Review site operations such as domains, DNS, published URLs, branches, site properties, contributors, and app installs.
- Check commerce work before risky changes: products, inventory, locations, categories, coupons, orders, refunds, gift cards, and pricing plans.
- Review Wix Events setup, events, ticket definitions, event categories, schedules, policies, and guest lists before changing registration, discovery, ticket-sale settings, category assignments, agenda details, or checkout/RSVP agreement text.
- Review bookings and scheduling information, including appointment availability, class event slots, multi-service slots, services, service options and variants, staff members, staff schedules, Bookings-visible calendar schedules, external calendar providers/connections/events, non-staff resources, resource types, locations, pricing-plan links, slugs, and add-on groups, before creating or changing a booking.
- Check marketing readiness across sender emails, sender details, sending domains, consent records, campaigns, campaign links, and donation campaigns.
- Inspect CMS data, collection structure, indexes, folders, permissions, cross-site sharing, and form submissions before changing live content.
- Build a saved plan for a live change so a person or reviewing agent can approve it before apply.

## What you should get back

When the tool is working well, the agent should give you:
- a clear summary in plain language
- the Wix area checked, such as Stores, Bookings, CMS, Marketing, Domains, or App Management
- the access path used, such as site app token or account API key
- a preview before any live change
- a chance to approve or stop
- a short record of what changed after live work

## Why this is better than a simple automation

A normal automation is useful when one Wix event should always cause one known action.

This tool is better when the job starts with a question: which site is affected, which records match, which permissions are available, and whether the proposed change is safe enough to approve.
