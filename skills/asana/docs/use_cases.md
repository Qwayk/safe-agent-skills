# What you can ask your agent to do in Asana

Start with a read. Once the agent has the correct workspace, project, team, portfolio, goal, or task, it can prepare a change for your approval.

## Understand current work

- "Show me the workspaces I can access and help me choose the right one."
- "Review this project for overdue, blocked, unassigned, or incomplete work."
- "Summarize what changed in this project since the last status update."
- "Check this portfolio and tell me which projects need attention."
- "Compare our goals with the projects and tasks supporting them."

## Prepare project work

- "Prepare a task for the launch checklist, assign it to this person, and show me the plan before creating it."
- "Move these reviewed tasks into the correct section, but do not apply anything yet."
- "Prepare a project status update from the latest task progress and wait for my approval."
- "Update this task's owner and due date after showing me its current state."

## Review teams and workspace setup

- "Check whether this team, project, and workspace membership setup matches the people who should have access."
- "Show me the custom fields used by this project and find tasks missing important values."
- "Review time-tracking entries and categories for this project."
- "Check which rules, webhooks, agents, or other automation are configured before we change anything."

## Work with collaboration and files

- "Show the recent stories and reactions on this task."
- "Prepare this comment for the task and wait because it will notify other people."
- "List the task's attachments and prepare this file upload for stronger approval."

## Handle wider or access-gated work

- "Check whether our account can read the audit log for this workspace."
- "Prepare an organization or resource export and explain how we will check its status."
- "Review available roles, access requests, memberships, budgets, rates, and approvals without changing them."
- "Show AI Studio usage or agents available to this service-account token, if Asana allows it."

Some asks depend on the Asana plan, user role, token type, OAuth scopes, or service-account access. A refusal from Asana means the command exists but this connection cannot use it; it does not justify switching to an arbitrary API request.
